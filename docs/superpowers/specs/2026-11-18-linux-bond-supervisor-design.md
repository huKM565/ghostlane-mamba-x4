# Linux 4x через одного root-supervisor

## Цель

IlyukhaLine на Linux TUN должен запускать настоящие пулы Mamba/VK/SaluteJazz 4x, показывать состояние каждой комнаты и восстанавливать упавшие комнаты без полного переподключения. Запуск и остановка пула не должны требовать по паролю на комнату. Настройки IlyukhaLine должны быть отделены от Ghostlane.

Сейчас `isBondedWindows` разрешает пул только для `WindowsTun`. Linux идёт по однокомнатной ветке и не создаёт `bondRoomStates`. Linux также использует общий с Ghostlane каталог `~/.olcbox`.

## Требования и критерии приёма

- Linux TUN использует тот же Xray roundRobin и sing-box front, что Windows 4x.
- Для Mamba, VK и SaluteJazz отображаются соответственно `M1–M4`, `V1–V4`, `J1–J4` с существующими правилами цвета и occupancy.
- Весь пул запускается через один вызов `LinuxPrivilege.command`: один `pkexec` вместо четырёх.
- Первый готовый путь поднимает туннель; остальные подтягиваются после готовности. Ни один нерабочий путь не попадает в Xray.
- Supervisor сам перезапускает завершившийся дочерний olcRTC с задержкой 2 секунды. После готовности комнаты существующий watcher обновляет Xray без смены TUN-facing порта.
- Остановка пула происходит до очистки TUN и не требует нового подтверждения: приложение создаёт stop-файл, supervisor завершает все дочерние процессы и выходит.
- Если мягкая остановка не удалась, существующая root-очистка завершает supervisor и все движки по имени его скрипта и конфигов. Supervisor не может перезапустить комнаты после начала очистки.
- Windows, Android, обычные однокомнатные профили и System Proxy не меняются.
- Настройки Linux хранятся в `~/.ilyukhaline`; `~/.olcbox` не изменяется и не удаляется.
- Первый запрос пароля проходит через системный polkit. Ошибка polkit 127 исправляется отдельным системным workaround и не маскируется кодом приложения.

## Рассмотренные подходы

### Один root-supervisor — выбран

Один привилегированный процесс владеет всеми дочерними olcRTC, их состоянием и перезапуском. Это сохраняет root-байпас TUN, даёт один диалог и позволяет останавливать пул без дополнительных прав.

### Отдельный pkexec на комнату — отклонён

Даёт четыре диалога при старте и новые диалоги при восстановлении. Кроме того, root-процессы нельзя надёжно остановить обычным `Process.destroy()` из приложения.

### Непривилегированные движки — отклонены

Текущий Linux TUN специально запускает olcRTC от root, чтобы исключить их трафик из своего маршрута. Запуск от пользователя без изменения маршрутизации вернул бы движки в их собственный туннель.

## Компоненты

### LinuxBondSupervisor

Новый небольшой Kotlin-компонент в `sharedUI/src/jvmMain/kotlin/org/olcbox/app/vpn/desktop/`.

Он создаёт в каталоге приложения Bash-скрипт и отдельный runtime-каталог пула. В скрипт не записываются комнаты, ключи или SOCKS-пароль: он получает только пути к уже созданным конфигам и runtime-каталогу. Конфиги остаются в существующем защищённом формате.

Скрипт:

1. Получает runtime-каталог, путь к olcRTC и список конфигов.
2. Для каждой комнаты создаёт отдельные `.log`, `.state` и `.pid` файлы.
3. Запускает все дочерние процессы и записывает состояния `up`/`down`.
4. Раз в секунду проверяет stop-файл и дочерние PID.
5. При неожиданном выходе помечает комнату `down` и перезапускает её через 2 секунды.
6. По stop-файлу, SIGTERM или SIGINT прекращает перезапуски, завершает все дочерние процессы и выходит.

Kotlin запускает этот скрипт ровно один раз через `LinuxPrivilege.command`. Мягкая остановка создаёт stop-файл и ждёт завершения supervisor до 5 секунд. Если supervisor не завершился, последующая root-очистка получает имя скрипта в список имён процессов для завершения.

### Связь с DesktopOlcRtcBond

`DesktopOlcRtcBond.Room` получает необязательные функции `isAlive` и общий `stopSupervisor`. Windows продолжает использовать настоящий `Process` каждой комнаты. Linux использует один `Process` supervisor и читает `.state` каждой комнаты; готовность по-прежнему подтверждается открытием её SOCKS-порта.

`recover` не создаёт новых pkexec: supervisor уже перезапускает процесс. Существующий `recoverDesktopBondRooms` лишь ждёт SOCKS и вызывает `markReady`. `stop` вызывает общий `stopSupervisor` один раз, а Windows по-прежнему останавливает каждый процесс отдельно.

`startDesktopBond` получает Linux-ветку только для создания процессов и чтения логов. Формирование конфигов, ожидание первой готовой комнаты, Xray, sing-box, rebalance и индикаторы остаются общими с Windows. Общий предикат переименовывается в `isBondedDesktopTun` и принимает только `LinuxTun` и `WindowsTun`.

Для каждой Linux-комнаты приложение читает её `.log` отдельной корутиной, пропуская строки через существующие `addLog`, `parseOlcRtcRoomParticipants` и `parseOlcRtcRoomState`. Читатели завершаются по generation/stop, поэтому старая сессия не может изменить индикаторы новой.

### Порядок остановки

`stopDesktopBond` вызывается до `linuxTunController.stop`. После мягкой остановки supervisor его runtime-файлы и конфиги удаляются. Если stop-файл не сработал, `LinuxTunController` завершает процессы по имени supervisor-скрипта и `olcRtcConfigNaming`, затем выполняет обычную очистку TUN/kill switch.

### Отдельный каталог и миграция

`DesktopPaths.appDataDir()` для Linux возвращает `~/.ilyukhaline`.

Однократная миграция выполняется до создания новых файлов и отмечается служебным marker-файлом. Из `~/.olcbox` копируются только отсутствующие в новом каталоге:

- `locations_v4.json`;
- `locations_v3.json`;
- `device_identity`;
- `desktop_socks_proxy_settings.json`;
- `desktop_connection_mode`.

Исходные файлы остаются на месте. Runtime, бинарники, TUN-кэши, логи и обновления не копируются. При прерывании миграции следующий запуск дополняет недостающие файлы; после marker ничего повторно не импортируется и удалённые пользователем настройки не воскресают.

## Ошибки и граничные случаи

- Ноль готовых комнат: старт завершается ошибкой, supervisor и все дочерние процессы останавливаются, Xray не создаётся.
- Одна–три готовые комнаты: туннель стартует только на них; остальные отмечены неактивными и восстанавливаются фоном.
- Все комнаты потеряны после старта: существующий watcher выполняет полный recovery, не создавая Xray с пустым списком путей.
- Ошибка записи stop-файла или зависший supervisor: используется root-очистка; kill switch остаётся в существующем безопасном состоянии.
- Отказ polkit: частично запущенный пул останавливается, ошибка показывается пользователю без повторного скрытого запуска.
- Старые `.log` не смешиваются с новой сессией: runtime-каталог каждого запуска уникален.

## Тестирование

### JVM и shell

Тесты пишутся до реализации и сначала наблюдаются красными.

- Генерируемый supervisor запускается с поддельным `olcrtc` на shell: создаются четыре процесса и состояния.
- После принудительного завершения одного процесса он перезапускается только для этой комнаты.
- Stop-файл завершает supervisor и все процессы без остаточных PID.
- Тестовый launcher фиксирует ровно один вызов привилегированного запуска на весь пул.
- `DesktopOlcRtcBond` учитывает `.state`, не вызывает per-room restart на Linux и вызывает `stopSupervisor` один раз.
- Исходный порядок остановки гарантирует supervisor до TUN cleanup.
- Предикат принимает Linux/Windows TUN и отклоняет System Proxy и обычные профили.
- Миграция копирует только разрешённые файлы, сохраняет оригиналы, не перезаписывает изменения и не переносит runtime.
- Полный `:sharedUI:jvmTest`, desktop compile и существующие deploy/gate tests остаются зелёными.

### Живая проверка на Linux

1. Подтвердить workaround polkit 127 через `systemctl stop polkit-agent-helper.socket`; постоянный mask применять только после успешного `pkexec id`.
2. Собрать `IlyukhaLine-1.0.472-amd64.AppImage` с pinned olcRTC, sing-box и Xray.
3. Подключить Germany Mamba 4x: один запрос пароля на запуск пула olcRTC, `M1–M4` становятся активными, TCP и UDP подтверждаются в Xray Германии. Существующие запросы для TUN/очистки не умножаются на число комнат.
4. Остановить `m1` на ВДС: `M1` краснеет, остальные пути продолжают переносить трафик; после восстановления `M1` возвращается без полного сброса TUN.
5. Повторить smoke для VK и SaluteJazz, проверить отсутствие лишних pkexec при восстановлении.
6. Отключиться: supervisor, движки и TUN завершаются; Ghostlane и `~/.olcbox` не изменяются.
7. Проверить готовый AppImage на наличие всех нативных ресурсов и положить его в `~/Загрузки`.

## Не входит

- Нагрузочное определение максимального числа Mamba-комнат на ВДС.
- Multi 8x/12x, MTS Link и Телемост.
- Изменение системного пароля пользователя или PAM-конфигурации.
- Перенос Linux-пула в System Proxy или macOS.
